How to read the map

The layout is a Gray code: bits 0–9 run along x and bits 10–19 along y, each in reflected-binary order. Two cells that touch differ in exactly one variable, so a lit patch is a set of solutions you can walk through by flipping one variable at a time. The map shows only part of that connectivity. Every assignment has 20 one-flip neighbours, and at most 4 of them touch it on a flat grid, so two islands that look separate may be one cluster in the cube. As α climbs, the lit patches shrink and vanish.

Dead cells are shaded by the clause that killed them, so the dark strata are the formula's history. Every count on this page is exact. The page records, for each assignment, the first clause it violates. The number of solutions with m clauses is then the number of assignments whose first violation comes at clause m or later.

Why it sits beside card 378

Card 378 is an algorithm claim: an upper bound on running time, stated in input length L = m(12n + 22) + n + 2. This page does not test that claim. It shows the objects the bound is measured over. The 4.26 mark is not from the card. It is the long-observed density where random 3-SAT flips from almost always satisfiable to almost never, and where random instances are empirically hardest for solvers. At that density the card's input length is about 51n².

At twenty variables the threshold is blurred. The formula shown here (seed 378) loses its last solution at m = 89, α = 4.45, and another seed will cross somewhere else nearby. As n grows, the drop in the chart sharpens into a cliff. A finite map can't show that limit, only the start of it.
