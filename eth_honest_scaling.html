The collection claims an algorithm that, for each fixed clause width k >= 2, writes out the exact number of satisfying assignments of a k-CNF formula on n variables, and a SAT bit, within C (L+1)^d 2^(A n f(n)) steps, where f(n) = (ln ln(n+16))^2 / sqrt(ln(n+16)) (natural logarithms, the +16 exactly as the Lean's runtimeScale n = n f(n) defines it) and C, A, d exist but are not given. This page shows what is counted, how a reduction changes n, and what the bound says as n grows. The small enumerations below are illustrations of the problem, not an implementation of the claimed algorithm.

1. Eight assignments

Three variables x, y, z give 2^3 = 8 assignments, one per corner of the cube (corner xyz = 101 means x true, y false, z true). Each clause you switch on removes the corners that falsify it. SAT asks one bit: does any corner survive? Counting asks how many.

2. A reduction budget

A graph problem becomes a CNF formula, and the formula's variable count n is what the claimed bound is in. Independent sets: one decision bit per vertex and one clause (not x_u or not x_w) per edge, so n = v. Perfect matchings: one decision bit per edge, then auxiliary variables for a circuit checking that exactly one chosen edge meets each vertex. The manuscript's corollary gives O(v+e) variables and clauses in total, with the auxiliary values uniquely determined by the edge bits (so the count is preserved), and states no constants. It is never just e variables.

Scaling the family: why v alone does not control the matching guarantee

Grow the graph to v = 10^s vertices. Dense family: keep the small graph's edge density p = e / (v choose 2), so e grows like p v^2 / 2. Sparse family: keep its average degree 2e/v, so e grows like v. Matching variables are taken as c (v + e) with an illustrative constant c (the manuscript gives none; this page's own example encoding uses 3e).

3. The exponent's long journey

The claimed bound is C (L+1)^d 2^(A n f(n)). Switch between the ratio f(n), the ratio A f(n) (which, for n > 0, decides whether the exponent term alone, 2^(A n f(n)), is below 2^n; at n = 0 both are 1) and the exponent A n f(n) itself, which grows without bound even when the ratio shrinks. The horizontal axis is doubly logarithmic, from n = 0 to about n = 10^3000; huge values are computed in logarithms, never formed. These are illustrative comparisons of upper bounds with unknown theorem constants, not running times. For each fixed k the theorem gives one machine and constants C, A, S, d, e (existential, no values); the A, C, d and L here are choices for illustration.

From the SAT bit: ETHDeciding 3-SAT in 2^(o(n)) would refute ETH (Impagliazzo and Paturi, 2001), and SETH with it, since SETH implies ETH. the decision consequence
Lower bounds proved assuming ETH or #ETHLose the force of that proof; they are not shown false, and another proof or a weaker hypothesis may still establish them. Example: Curticapean's #ETH-conditional bound for counting perfect matchings in sparse bipartite graphs, which the paper's corollary addresses directly.
