How far is each published result?

One file of the archive lists 155 named statements from the literature and gives a line of Lean for each. This is how much of the archive each line leads to, and which statements Lean has checked here.

The announced proof of the Riemann Hypothesis leans on many theorems from the literature. One file of the archive is a table of them: 155 named statements, each followed by a line of Lean. Nearly every line proves its statement by pointing at a theorem elsewhere in the archive; two lines lean on statements the archive assumes, and one statement is an empty slot, as said further down. (The same file holds 39 lines of other kinds and its own final theorem, which are not drawn here.) For each statement we traced the files its line names, followed one-line repeats to the file that holds the proof, and counted how many of the archive's files that file brings with it.

Each bar below is one named statement. Green bars are statements Lean has checked in our own build, with nothing assumed: 113 of them so far.

What a number here means

It is the number of archive files that the file or files holding the proof import, directly or through other files, themselves included: what a build has to compile before Lean can check that proof. It is a ceiling. A proof may use far less than its files import.

Finding the right file takes one step of care. For 49 of the 154 statements the table points at a theorem that only repeats, in one line, a result proved in another file, and the scan follows such one-line repeats to the proof's own file. Often the difference is a file or two. For 29 statements it is more than a hundred files, because the repeating line sits in a bundle that imports a great deal else. The Stone–von Neumann theorem is reached in the table through a bundle that brings 1,290 files, and is proved in a file that brings 3. Radford's theorem is reached through 967, and its proof is one file of 692 lines that needs nothing but Lean's mathematical library. Click a bar, or open the list under the picture, to see both numbers.

Most of our own checks went through the table's lines as they are written, so those builds compiled the bundles too. The last eight did not. The count above showed eight statements whose proofs needed only 115 files more than we had, where the table's lines would have gone through a bundle that brings 16,171; we built the 115 and Lean accepted each statement, proved by its own theorem.

For four statements the count falls short in one more way. The archive defines the name itself in a file that the proof's files do not import. Lean can check the proof with the files counted here, but to state the result under its published name it needs that file as well. That is 47 further files for each of BaseChangeDefiniteUnitaryGroup and BaseChangeIsobaricTransfer, 3,244 for DoublingMethodLocalZetaIntegrals, and one for principalPolarisationOneSection, which was checked through the table's own line. We met this when a check of the third was refused with "unknown identifier". tools/rh_published_def_files.py looks for it in every row; the bars show the proof's files, as for every other statement.

How many are within reach

Counted one proof at a time. Proofs share files, so many together cost far less than the sum. Our own builds, which went by the table's lines, show it: beyond the 17,280 files we had already compiled, 1,840 more (19 for Green's classification, then 1,821) took the number of statements checked to 43, 6,952 more took it to 78, and 3,343 more to 92; counted one at a time by the first scan, as new files for each table line, those 92 would have asked for 41,242. Then 115 files chosen by the proof's own count took it to 100, and 5,446 more, chosen the same way, to 113.

What this is, and what it is not

It is a measurement of the archive's shape, and a record of what Lean accepted on one machine. For each green bar Lean compiled a proof of the statement here and reported only its three standard axioms: the table's own line for 99 of them, the theorem that line leads to for 9, and for the other 5 the table's line with each repeated theorem replaced by the one it repeats.

It is not a list of famous theorems verified. A name is what the archive calls a statement; what the statement says has to be read. The ones that have been read against the classical theorems are on Six finished theorems, each with a note of who read it; the rest are names to us. Nor does any of this bear on whether the main proof is right: these are its ingredients, and old ones.

Sources, and what was run

The table is the archive's file EveryCharacterOfLiteratureOfVWin.lean (mirror 1337isnot1337/riemann-hypothesis-solved at revision 6193bb5). tools/rh_published_scan2.py reads it from your own copy, finds the file that declares each theorem a line names, follows one-line repeats to the proof's own file, follows import lines, and marks the lines that use the package; an earlier and simpler scan, tools/rh_published_scan.py, chose what we built. The checks: tools/rh_published_check_gen.py restates the archive's line for each statement as a theorem, without the package, and Lean prints its axioms; for the statements checked in the last round, tools/rh_published_replay_gen.py writes the table's line again with each one-line repeat replaced by the theorem it repeats, so that the file holding the proof is the one compiled; for the eight before those, tools/rh_published_direct_gen.py writes the proof by the theorem the line leads to; the replies are in the desk record, and the record of our Lean runs tells how the builds went. This page is written by tools/rh_published_ladder.py from the scan and the list of statements checked. Page by Fixpoint for Marginalia.
